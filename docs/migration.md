# macOS 选择性迁移指南

[返回 README](../README.md) · [依赖与版本快照](dependencies.md)

## 0. 触发与边界

仅当用户明确要求安装、迁移或采用此仓库配置时，才进入本流程。普通编码任务、读取 README、克隆仓库、发现缺失依赖，都不是安装授权。

本指南不要求全装，不提供覆盖式初始化。不在作者环境重装来证明可迁移；本次文档核对不等于接收方机器验收。其他系统暂停套用 macOS 步骤，另行设计适配。

## 1. 先询问并记录

已有明确答案无需重复问；缺失项在变更前确认：

- macOS 版本、CPU 架构、终端；已有 Pi/Node/npm/Python/uv 的版本与安装方式。
- 仓库所在路径、目标 agent 目录（默认 `~/.pi/agent`，可能由 `PI_CODING_AGENT_DIR` 改写），是否已有配置、项目级 `.pi/` 和待保留规则。
- 要采用哪些功能组，哪些明确不要；是否需要外部技能、MCP、通知、子 Agent。
- 可用模型提供方和模型 ID：主模型、记忆模型、子 Agent 分别选。只问名称与可用性，不让用户把密钥发到聊天。
- 通知平台（本机或远端）、是否愿意授予系统通知权限；浏览器使用方式与调试端点、输出目录、允许访问的目录。
- 是否允许联网下载、安装包、修改指定文件；备份位置与回退范围。补丁另行审批。

最小选择可以只有行为规则或几个技能，不需要全套插件。

## 2. 只读盘点与变更预览

将仓库放在独立检视目录，不直接覆盖目标 home。对照依赖表，查看目标安装版本的官方文档/帮助；本指南依据 Pi **1.3.0** 本机文档，未来接口可能变化。

预览至少包含：

| 项目 | 必须说明 |
|---|---|
| 文件 | 源路径、目标路径、新增/逐字段合并/不改、冲突处理 |
| npm 与 CLI | 选中包、版本或范围、下载来源、安装方式及副作用 |
| 资源 | 保留的过滤规则、不会加载的资源、可能重复的命令 |
| 外部依赖 | 缺失目录/符号链接/独立仓库、由用户补充还是跳过 |
| 模型与服务 | 接收方模型选择、认证方式、联网/费用边界 |
| 验证与回退 | 每组最小检查、备份路径、恢复范围 |

**等用户确认这份预览后才修改。** 不把 `plans/`、扩展内部 `task_plan.md`、技能实现计划当安装清单；不猜测缺失包、技能或独立仓库的替代来源。

## 3. 备份与最小基础环境

关闭可能写配置的 Pi 会话，或约定迁移期间不并行修改。先将目标文件备份到用户私有、仓库外的位置，记录哪些原本不存在。备份可能含敏感信息，不上传、不提交、不向模型打印。不要把作者 home 的认证、会话、缓存、信任和授权记录复制过去。

已有可用 Pi 时优先保留，不默认升级。本机 1.3.0 官方 README 给出的两种安装方式如下，**仅供确认后择一执行**：

```bash
# 官方安装器：下载并执行脚本，先审阅来源；管理的发行包锁定传递依赖
curl -fsSL https://pi.dev/install.sh | sh

# 或 npm 安装：要求 Node.js >=22.19；不锁定传递依赖
npm install -g --ignore-scripts @earendil-works/pi-coding-agent
```

这两个命令都不是固定安装 1.3.0 的复现命令。需要特定版本时，先核对该版本支持的安装方式，不能把本机目录 `install/releases/1.3.0/` 当可移植安装包。

安装后核对 `pi --version`。认证通过 Pi `/login` 或提供方的安全渠道完成，不运行输出密钥的命令。自定义提供方需接收方自行配置，不能靠复制 `settings.json` 得到可用模型。

## 4. 按组恢复与合并

### npm 包与资源过滤

逐个选择 [依赖表](dependencies.md) 中的包；不要原样导入整个 `packages` 数组。

```bash
# 示例：只有用户选择了此功能并批准安装后才执行
pi install npm:@juicesharp/rpiv-todo
pi list
```

Pi 的个人包声明保存在目标 agent 目录的 `settings.json`；`--local` / `-l` 改写项目 `.pi/settings.json`，项目资源还受 trust 控制，不能混用范围。

若用户批准先合并选中声明，再统一恢复，可使用 **`pi update --extensions`** 协调安装；它涉及该配置的所有包，未锁版本包可能更新。`pi update` 单独运行更新的是 Pi 本体，**不是仅恢复插件**。不要为方便执行 `pi update --all`。

保留对象形式的过滤条件；装包后再次核对，因为声明存在不等于资源已加载：

- 字段省略：加载包允许的该类资源；`[]`：不加载该类资源。
- `!pattern` 排除 glob；`+path` 精确包含；`-path` 精确排除。过滤只能收窄包 manifest 允许的资源。
- `@gotgenes/pi-permission-system` 的四类资源目前均为 `[]`，不能声称它正在实施权限规则，也不能顺手启用。
- `pi-openai-fast-mode` 的 `extensions: []` 必须与本地 Ultrafast 包装器一起理解，避免重复命令。
- `@ff-labs/pi-fff` 保留 `extensions: ["+src/index.ts"]`。
- 顶层继续保留 `-extensions/pi-guided-plan/src/index.ts`、`-builtin:mcp` 和技能 `-skills/plan-loop/SKILL.md`；改变它们是新的决定，不是依赖修复。

可用 `pi config` 检查资源开关，但不要把检查变成默认启用。多个设置文件、toggle 配置和项目覆盖可能改变实际状态，最终以启动诊断为准。

### 本地扩展、规则与技能

只复制选中的源码和必要配置，不复制 `node_modules`。本地包不会由 Pi 自动安装依赖，按其 manifest 单独预览依赖安装。

- `AGENTS.md`、`APPEND_SYSTEM.md` 是全局行为偏好，先选条款再合并，不能覆盖接收方已有规则。检查里面的路径、模型、工具和技能假设。
- `pi-ultrafast` 依赖安装目录中的 `pi-openai-fast-mode`，还可能产生额外费用；保留关闭状态，启用须明确请求。状态指示不证明服务端接受或加速。
- `model-skill-gate` 的配置与 superpowers 在仓库外；选择此功能才处理，不能把 gated skills 直接放到全局扫描目录来“修复”缺失。
- 四个技能符号链接只提供路径，不提供目标内容。`~/.agents/skills/` 的其他技能也不是本仓库交付物；补齐经用户确认的来源，或跳过并报告。

### MCP 与搜索

当前选用 `pi-mcp-adapter`，内置 `builtin:mcp` 被排除。不要同时启用两套 MCP 实现；原生 Pi 的 MCP CLI 文档不能自动视为适配器的等价管理接口。

合并 `mcp.json` 时重选浏览器端点、输出目录和允许根目录，FOFA 路径指向接收方安装位置。逐台服务器验证，不先连接全部。浏览器、远端服务和搜索服务使用接收方自己的认证；不复制 cookie、会话头、OAuth 缓存或 FOFA 账户资料。

### 通知与可选补丁

选择 `@pi-unipi/notify` 后再配置平台及事件路由，核对 macOS 通知权限、勿扰模式及终端环境。远端通知凭据通过插件支持的安全方式设置，不写分享文档。

[补丁说明](../patches/README.md) 描述历史横幅不归档问题，**不是必装步骤**。当前包快照为 2.20.5，脚本注释中的 2.16.0 回退示例不能照抄。

只有确认问题可复现、检查当前 `platforms/native.ts` / `platforms/node-notifier.d.ts` 与脚本锚点、备份两文件，并取得单独批准后，才考虑执行补丁。脚本可能先改一个文件再在另一个失败，不应视为事务；失败立即停止，按备份恢复。本次核对没有执行它，也未证明当前版本需要它。重装后应重新判断，而不是无条件重跑。

## 5. 分组验收

安装/调用/发送通知均需前述授权；下面是接收方的验收清单，不是本次已通过记录：

| 组 | 最小验收 |
|---|---|
| 基础 | 版本与目标 agent 目录正确；启动无所选资源的加载错误 |
| 包与过滤 | `pi list` 和 `pi config` 与选择一致；原禁用资源未被意外启用 |
| 模型 | 可选列表含选定模型；用户批准后最小请求成功；主模型与记忆模型分别确认 |
| 技能/本地扩展 | 路径可解析；技能无同名冲突；选定扩展命令存在，依赖缺失明确报告 |
| MCP/Tavily | 单个服务最小无敏感查询成功；未选服务不启动，浏览器目录边界正确 |
| 通知 | 用无敏感文本发一次测试，检查接收与消息中心；不重复触发生命周期通知 |
| PDF/浏览器/子 Agent | 仅验证选中功能；使用无敏感样例，子 Agent 单独确认模型与预算 |

修改配置后按对应插件说明 `/reload` 或重启；**加载成功不等于实际功能成功**，文件存在也不等于依赖可执行。不要用带凭据的完整配置、环境变量列表或会话日志证明成功。

报告逐组列出：通过、失败、未运行、未解决。服务未授权、依赖不存在或版本不兼容时停止该组，保留已验证部分，不猜替代方案。

## 6. 回退

- 停止相关会话，恢复本次修改的文件；只删除本次新增且事先记录的文件，不覆盖迁移后用户的新工作。
- 包移除使用 `pi remove <source>` 会修改声明；先比较当前配置与备份，不批量移除原有包。安装更新过原有依赖时，恢复配置本身不足以恢复依赖版本，需按记录另行批准重装。
- 本地扩展/技能退回原位置和过滤状态；通知补丁恢复两份备份，随后按插件说明重载。
- 恢复目标配置后重复最小启动检查。不要 `git reset --hard`、清空整个 agent 目录或复制作者认证作为补救。
